# CompressKit — animation-first production plan

Status: silent visual cut. Voiceover will be generated by the user in Sarvam or ElevenLabs.
Format: 1920×1080, 30 fps, 178 seconds. All timings are provisional until voiceover is supplied.

## Voice direction

Clear, confident English; conversational technical explanation. Maintain a natural pace around 150–160 words per minute. Short pauses between paragraphs. Read the opening directly, with no greeting or introductory music pause. Do not read scene labels or production notes. No background music in the voice export.

Use VOICEOVER.txt for one continuous generation. For precise synchronization, use the files in voice-segments/ separately, with the same voice and settings, and export as 01.wav through 11.wav (MP3 also works). The sync_voice.py utility retimes video to the speech, never the speech to the video.

## Shot plan

### 01. A MODEL, TRANSFORMED
Time: 00:00–00:11 | frames 0–329

Camera pushes through stacked feature-map planes. Alternating channels separate and disappear; the remaining network contracts. No logo introduction.

**Voiceover:** Here’s how CompressKit makes an AI model smaller and faster, while measuring the accuracy it gives up. We start with a trained image classifier.

### 02. FROM PIXELS TO PREDICTION
Time: 00:11–00:30 | frames 330–899

A real CIFAR-10 cat image appears. A highlighted filter window scans across it, with an illustrative edge response beside it. Cut to the complete network: signals travel through feature-map stacks into animated class-score bars.

**Voiceover:** An image enters the network as numbers. Convolution filters scan small regions, detecting patterns such as edges. Deeper layers combine patterns into useful features. The final classifier produces class scores. The highest score becomes the prediction.

### 03. MEASURE THE ORIGINAL
Time: 00:30–00:44 | frames 900–1319

Original network remains intact as baseline metrics appear. Cut into a CPU diagram; a scanning line and flowing circuit paths visualize the hardware probe.

**Voiceover:** Before compression, we preserve the original model and measure its accuracy, latency, and file size. We also check the CPU, because lower precision is only useful for speed when the hardware and runtime support it.

### 04. REMOVE CHANNELS, NOT JUST VALUES
Time: 00:44–01:02 | frames 1320–1859

Weights turn to zero without the matrix shrinking. Match cut to complete feature channels: selected channels separate, fall away, and neighboring channels close the gaps. Connections remain visible.

**Voiceover:** First, structured pruning. A channel represents a learned feature map. We remove selected channels and update the connected layers together. The tensors become smaller, so the network requires less computation. Simply replacing individual weights with zeros would not shrink those dimensions.

### 05. CUT. RECOVER. REPEAT.
Time: 01:02–01:17 | frames 1860–2309

An accuracy trace draws in real time. The active point drops during pruning and climbs during recovery. Labels alternate between PRUNE and FINE-TUNE. The curve is explicitly conceptual.

**Voiceover:** Removing too much at once can damage accuracy. Instead, we can prune gradually and fine tune between cuts. Batch normalization recalibration updates the changed network’s activation statistics. These recovery steps can help, but they cannot guarantee the original accuracy.

### 06. LET THE TEACHER GUIDE THE STUDENT
Time: 01:17–01:34 | frames 2310–2819

The teacher and student networks pulse independently. Streams of signals flow from teacher to student. The student’s illustrative class-score bars gradually approach the teacher’s bars.

**Voiceover:** Next, knowledge distillation. The untouched original model becomes the teacher. The smaller model is the student. The student learns from correct labels and the teacher’s class scores, helping it recover useful behavior. Only the student is needed for deployment.

### 07. THE SAME WEIGHTS. FEWER BITS.
Time: 01:34–01:52 | frames 2820–3359

Thirty-two bit cells collapse into eight cells. Cut to a number line: floating values move onto quantized levels. A scale-and-zero-point equation explains the mapping.

**Voiceover:** Quantization reduces numerical precision. Thirty two bit floating point values are mapped to eight bit integers using calibrated scales. For the same weight count, raw weight storage can become about four times smaller. The complete file reduction varies, and some operations may stay in floating point.

### 08. LEARN TO TOLERATE ROUNDING
Time: 01:52–02:05 | frames 3360–3749

An irregular quantized signal gradually approaches a reference. A backward arrow indicates weight adaptation; the captions separate training-time simulation from deployment quantization.

**Voiceover:** If rounding causes too much accuracy loss, quantization aware training simulates that error while the model is still trainable. The weights adapt before the final low precision model is exported.

### 09. THE AUTOMATIC DECISION LOOP
Time: 02:05–02:26 | frames 3750–4379

Data packets move through a decision tree. Quantization is tried first; accuracy-only failure branches toward protection and recovery, while size/latency failure branches toward pruning. The budget is labeled as an example.

**Voiceover:** You can choose the stages manually, or give the toolkit a budget. Automatic search tries quantization first. If only accuracy fails, it can protect sensitive layers and try recovery. If latency or size fails, it explores pruning. Every candidate is measured. It stops when a configuration meets the requirements, if one is found.

### 10. PROOF FROM A RECORDED RUN
Time: 02:26–02:46 | frames 4380–4979

Baseline bars appear, followed by compressed bars. Ratios count up to 6.2× and 2.25×. Accuracy loss counts to 2.68 percentage points. The model, dataset, and measurement host remain visible.

**Voiceover:** Here is one recorded result for ResNet fifty six on CIFAR ten. The model shrank from three point two eight to zero point five three megabytes, and inference became two point two five times faster. Accuracy changed from ninety three point one eight to ninety point five zero percent.

### 11. DEPLOY THE COMPRESSED MODEL
Time: 02:46–02:58 | frames 4980–5339

The input image travels through a compact network toward a class prediction. Output labels show the model and reporting artifacts. End on the deployment result rather than a prolonged logo card.

**Voiceover:** The final output is an ONNX model, with reports showing exactly what changed. A new image passes through the compressed network and produces a prediction. Less storage. Faster measured inference. An explicit accuracy trade off.

## Sources and visual semantics

- Recorded result: frontend-next/src/data/models.json, ResNet-56 / CIFAR-10, Intel i5-11320H. These results have not been rerun for this film.
- Input image: local CIFAR-10 test image 224. It is used as an illustration, not as calibration data.
- Edge response: an illustrative image edge filter, not a captured CNN activation.
- Network planes, class scores, quantization levels, and recovery curves are explanatory diagrams, not literal layer dumps or experimental traces.
- INT8 gives approximately 4× raw weight storage reduction only at equal weight count; deployed file reduction and speed vary.
- No synthetic voice or music is included in the new visual cut.
